# ADR-002. Выбор способа взаимодействия мобильного приложения с backend

**Дата:** 2026-11-04  
**Статус:** Принято для проектирования

**Контекст:**

Мобильное приложение и backend разрабатываются отдельно. Они должны обмениваться фотографиями, данными карточек, списками слов и результатами тренировок. Необходимо выбрать единый способ такого взаимодействия.

**Ограничения:**

- Приложение должно поддерживать Android (НФТ-6).
- Для серверных функций требуется подключение к интернету (НФТ-10).
- Фотографии и персональные данные пользователей необходимо защищать при передаче (НФТ-7, НФТ-8).
- Основные действия пользователя выполняются отдельными запросами к серверу.
- Команда уже работала с REST API, но не использовала GraphQL и WebSocket на практике.

**Рассмотренные варианты:**

1. **REST API:** клиент отправляет отдельные HTTP-запросы для получения, создания, изменения и удаления данных.
2. **GraphQL:** клиент указывает в запросе, какие именно данные и поля ему нужны. Это удобно для сложных выборок, но требует отдельного проектирования схемы.
3. **WebSocket:** клиент и сервер устанавливают постоянное соединение и могут обмениваться сообщениями в обе стороны. Подходит для чатов и функций реального времени.

**Решение:**

Выбран REST API. Передача данных между мобильным приложением и backend будет выполняться по HTTPS.

**Обоснование:**

- **Подходит для функций Word Hunt:** пользователь выполняет отдельные действия — отправляет фото, сохраняет карточку, открывает словарь или отправляет результат тренировки. Для них достаточно обычных запросов к серверу.
- **Простота разработки:** REST API удобно документировать, тестировать и использовать при отдельной разработке frontend и backend.
- **Опыт команды:** команда уже работала с REST API, но не использовала GraphQL и WebSocket. Поэтому знакомый вариант позволит не тратить дополнительное время на изучение новых технологий.
- **Нет необходимости в постоянном соединении:** основные функции Word Hunt не требуют непрерывного обмена сообщениями.

HTTPS выбран отдельно от REST API, потому что он защищает передачу данных с помощью TLS. Это важно для фотографий и персональных данных пользователей.

**Недостатки решения:**

- Для получения разных данных может потребоваться несколько запросов.
- Изменения API необходимо согласовывать между frontend и backend.
- При отсутствии интернета серверные функции будут недоступны.
- Для HTTPS необходимо настроить сертификат и защищённое соединение на сервере.

**Последствия:**

- Для основных действий приложения будут определены адреса запросов и HTTP-методы, например `GET /cards`, `POST /cards`, `PATCH /cards/15` и `DELETE /cards/15`.
- Обычные данные и ответы API будут передаваться в формате JSON.
- Фотографии будут загружаться отдельным файлом через `multipart/form-data`.
- Все запросы с мобильного приложения к backend должны выполняться по HTTPS.
