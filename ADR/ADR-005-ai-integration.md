# ADR-005. Выбор способа подключения нейросетевой модели

**Дата:** 2026-11-04  
**Статус:** Принято для проектирования

**Контекст:**

Word Hunt использует нейросеть для распознавания предметов на фотографиях. В будущем может потребоваться заменить модель из-за низкой точности, высокой стоимости или медленной работы. Необходимо организовать подключение так, чтобы замена нейросети не требовала изменений во всём backend и мобильном приложении.

**Ограничения:**

- Мобильное приложение должно взаимодействовать с нейросетью через backend.
- Остальные модули backend не должны зависеть от особенностей конкретной нейросети.
- Пользователь должен иметь возможность исправить предложенное слово или ввести его вручную.
- На начальном этапе планируется использовать одну нейросетевую модель.
- Конкретная модель и способ её запуска пока не выбраны.

**Рассмотренные варианты:**

1. **Мобильное приложение обращается к AI-сервису напрямую:** Android самостоятельно отправляет фотографию выбранному провайдеру.
2. **Backend обращается к нейросети напрямую из разных обработчиков:** код работы с конкретной моделью размещается непосредственно в обработчиках запросов.
3. **Отдельный модуль распознавания:** backend передаёт фотографию специальному модулю, который отвечает за взаимодействие с нейросетью и возвращает результат в едином формате.

**Решение:**

Выбран отдельный модуль распознавания с единым интерфейсом. На начальном этапе будет использоваться одна выбранная нейросетевая модель. Мобильное приложение отправляет фотографию backend, который передаёт её модели через модуль распознавания.

**Обоснование:**

- **Возможность замены:** при переходе на другую нейросеть потребуется изменить её подключение внутри модуля распознавания, а не код словаря, карточек и мобильного приложения.
- **Безопасность:** если будет использоваться внешний AI-сервис, его секретные ключи будут храниться на backend, а не в Android-приложении.
- **Единый формат результата:** остальные части backend будут получать результат распознавания в одинаковом формате независимо от используемой модели.
- **Разделение ответственности:** взаимодействие с нейросетью будет находиться в одном месте, что упростит разработку и тестирование.

**Недостатки решения:**

- Появляется дополнительный модуль, который необходимо разработать и поддерживать.
- При замене нейросети может потребоваться адаптация её результата к формату приложения.
- Работа распознавания зависит от скорости и доступности выбранной модели.
- Единый интерфейс не гарантирует одинаковую точность разных моделей.

**Последствия:**

- В backend будет создан отдельный модуль распознавания с единым интерфейсом.
- На начальном этапе используется одна нейросетевая модель.
- Остальные модули backend взаимодействуют с модулем распознавания, не зная особенностей конкретной модели.
- Автоматическое переключение на резервную нейросеть не предусматривается.
- Если распознавание не удалось, пользователь сможет повторить попытку или ввести слово вручную.
- Если используется внешний AI-сервис, его ключи хранятся на backend. При самостоятельном запуске модели ключ стороннего провайдера не требуется.
- При необходимости замены нейросети изменяется реализация модуля распознавания, а остальная система сохраняет прежний способ взаимодействия с ним.
