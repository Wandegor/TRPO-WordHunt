# ADR-008. Фиксация результатов тренировок и расчёт прогресса

**Дата:** 2026-11-04  
**Статус:** Принято для проектирования

**Контекст:**

В процессе повторения карточек пользователь отмечает результат («Помню» или «Не помню»). Приложению необходимо отображать статистику: общее число повторений, регулярность занятий, динамику изучения. Необходимо определить формат сохранения данных о повторениях.

**Ограничения:**

- Сохранение результатов каждого цикла повторения без риска потери данных (ФТ-23–26, НФТ-3).
- Обеспечение расчёта показателей прогресса, регулярности и серий занятий (ФТ-27–30).
- Исключение избыточных дублирующих хранилищ на этапе MVP.

**Рассмотренные варианты:**

1. **Хранение только суммарных счётчиков:** инкремент полей `correct` и `incorrect` у карточки. Теряется хронология и время ответов.
2. **Логирование каждого отдельного ответа:** сохранение отдельной строки для каждого действия с фиксацией идентификатора карточки, пользователя, результата и точного времени.
3. **Комбинированный подход:** одновременная запись истории и синхронное обновление готовых витрин данных.

**Решение:**

Выбрано логирование каждого отдельного ответа (Вариант 2).

**Обоснование:**

- **Сохранение временного контекста:** фиксация точной временной метки (`answered_at`) позволяет рассчитывать регулярность занятий и серии дней без потери хронологии.
- **Гибкость для будущих алгоритмов:** накопленная история повторений позволит в дальнейшем внедрить интервальное повторение без изменения схемы данных.
- **Простота транзакций:** операция записи ответа атомарна и не требует синхронной координации нескольких таблиц при завершении тренировки.

**Недостатки решения:**

- Быстрый рост объёма таблицы результатов при активном использовании приложения.
- Повышение нагрузки на БД при расчёте аналитических показателей «на лету» без использования индексов и агрегатов.

**Последствия:**

- В PostgreSQL создаётся таблица истории повторений с полями `card_id`, `user_id`, `result`, `answered_at`.
- Базовая статистика для MVP рассчитывается агрегирующими запросами по сохранённым записям.
- Реализация сложного интервального повторения откладывается до следующих релизов.
