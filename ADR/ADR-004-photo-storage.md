# ADR-004. Выбор способа хранения фотографий пользователей

**Дата:** 2026-11-08  
**Статус:** Принято для проектирования

**Контекст:**

Фотографии — важная часть Word Hunt. Они используются при создании карточек и во время повторения слов. Необходимо выбрать, где хранить изображения и как связывать их с карточками.

**Ограничения:**

- Фотографии являются файлами и могут занимать значительно больше места, чем текстовые данные карточек.
- Доступ к фотографиям должен быть только у владельца соответствующей карточки.
- Для MVP желательно обойтись без отдельного облачного хранилища.
- Фотографии должны включаться в резервное копирование вместе с данными приложения.
- Для загрузки поддерживаются JPEG и PNG. Размер файла, отправляемого на сервер, не должен превышать 5 МБ.

**Рассмотренные варианты:**

1. **Хранить фотографии в PostgreSQL:** изображения сохраняются непосредственно в базе данных вместе с остальной информацией.
2. **Хранить фотографии в папке на сервере:** изображения сохраняются отдельными файлами, а в базе данных хранится путь или идентификатор файла.
3. **Использовать объектное хранилище:** фотографии хранятся в отдельном сервисе, например S3-совместимом хранилище.

**Решение:**

Для MVP выбрано хранение фотографий в закрытой папке на сервере. В PostgreSQL будут храниться только идентификатор фотографии и связь с карточкой.

Фотографии сохраняются в JPEG с длинной стороной не более 1600 пикселей. Пропорции сохраняются, небольшие изображения не увеличиваются. Это ограничения проекта для уменьшения объёма фотографий.

**Обоснование:**

- **Разделение данных:** фотографии — большие файлы, а в базе данных находятся текстовые данные и связи между ними. Хранение отдельно не будет излишне увеличивать размер базы.
- **Простота реализации:** обычная папка на сервере позволяет хранить и получать фотографии без подключения дополнительных сервисов. Для текущего масштаба Word Hunt этого достаточно.
- **Контроль доступа:** фотографии будут выдаваться через backend после проверки владельца карточки.
- **Возможность замены:** при росте проекта локальное хранение можно заменить объектным хранилищем.

**Недостатки решения:**

- Необходимо отдельно создавать резервные копии базы данных и папки с фотографиями.
- При запуске нескольких экземпляров backend локальные файлы могут оказаться недоступны на другом сервере.
- Нужно следить за удалением ненужных файлов и не допускать прямого публичного доступа к папке.

**Последствия:**

- Имена файлов и их расположение назначает сервер.
- В базе данных хранится путь или идентификатор фотографии, а не само изображение.
- Доступ к фотографии предоставляется только после проверки прав пользователя.
- Временные фотографии до создания карточки хранятся отдельно от постоянных (ADR-006).
- При масштабировании приложения потребуется рассмотреть общее файловое или объектное хранилище.
- Мобильное приложение уменьшает фотографии перед отправкой. Backend проверяет фактический формат и размер файла и сохраняет изображение в выбранном формате.
- Перед сохранением учитывается ориентация фотографии и удаляются метаданные, включая геолокацию. Прозрачность PNG заменяется белым фоном.
